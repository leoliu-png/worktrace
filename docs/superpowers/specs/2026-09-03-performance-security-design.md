# WorkTrace 性能、检索与安全加固设计

## 目标

让控制台在日志数量增长后仍能快速切页与检索，并让 API 上传在空值、重试、并发和异常情况下保持安全、可预测的行为。

## 范围

本次覆盖控制台日志读取、SQLite 数据访问、工作日志 API 上传和授权边界。不改变现有 Google 登录与 API Key 的用户体验，也不实现 MCP 或 Skill 接入；这两项作为后续独立集成说明。

## 性能与体验

- 控制台页面的当前用户读取使用 React 请求级缓存，避免一个页面内重复查询会话与用户。
- SQLite 启用 WAL、foreign keys 与合理的 busy timeout，降低并发读写导致的瞬时失败。
- 日志查询在数据库中完成，按 `created_at DESC, id DESC` 使用游标分页；列表首屏只读取有限条结果，页面提供“加载更多”。
- 为作者、创建时间及 API Key 查询建立索引；关键词检索使用 SQLite FTS5，并按标题、已完成、进行中、阻塞和计划字段索引。

## 检索接口

数据库暴露统一的日志查询参数：`authorId`、`dateRange`、`query`、`cursor`、`limit`。结果包含 `items` 和下一页游标。

关键词为空时仅使用普通索引查询；有关键词时由 FTS5 匹配后再联合作者、日期范围过滤。人员和日期筛选仍可与关键词同时生效。

## 上传可靠性与安全

- API 先完成认证，再读取和解析请求体；请求体设定大小上限，格式错误和字段错误返回统一的 JSON 错误格式。
- API 日志上传接受 `Idempotency-Key`。同一用户、同一键、同一请求重试返回已创建的同一日志，不再重复插入。
- API Key 以固定长度查找前缀定位候选密钥，再用常量时间比较哈希；不再遍历全部有效密钥。
- 有效 API Key 默认只能读取自己的日志。管理员才能显式请求团队日志。
- 生产环境缺失 `KEY_ENCRYPTION_SECRET` 时应用拒绝启动；开发环境才允许使用开发密钥。
- 数据库事务保护管理员降级/删除中的最后管理员检查；数据库错误、冲突和忙等待映射为不泄露内部细节的响应。
- 审计事件记录敏感操作的主体、类型与目标 ID，不记录 API Key 明文、请求正文或内部异常堆栈。

## 部署边界

本阶段的 SQLite busy timeout 与幂等约束适用于单个应用实例。若部署多个应用实例，限流和幂等应迁移到 Redis 或 PostgreSQL 等共享存储；这是上线拓扑变更时的必做项。

## 验证

- 为分页、组合筛选、幂等上传、权限拒绝、无效 JSON、空值和最后管理员并发保护添加测试。
- 运行完整测试与生产构建。
- 验证 API 响应不包含 API Key 明文或内部错误栈。
