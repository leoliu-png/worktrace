# WorkTrace 自动优化 v3（本地）

巡检 Agent 从用户角度发现问题；做事 Agent 在一个持续会话中定位、修改并按当前需求验证；独立评审 Agent 审核最终候选。正常修复不再启动单独的诊断 Agent 或浏览器复测 Agent。

## 运行流程

1. 用户提交反馈，或巡检 Agent 定期/手动体验本地 WorkTrace 并提交带复现证据的建议。未完成的重复反馈保持可处理；已完成、人工处理的反馈跳过。
2. 程序读取反馈和附件，创建隔离候选工作目录以及开发预览。做事 Agent 同时使用分段源码读取、局部补丁和本地浏览器，自行复现、定位、修改并选择本条需求所需的验证。安全产品文件可在当前调用内补充写入范围，受保护文件仍禁止。
3. 做事 Agent 报告根因、修改范围、验收项以及实际验证证据。工具无法完成的部分记为待人工验证；已发现的产品缺陷必须继续修复。没有固定测试套件或固定图片探针必跑要求，也不要求新建单元测试。
4. 程序仅执行 lint、TypeScript 类型检查和构建。检查失败返回具体错误给原做事 Agent 会话，不重新开诊断，不执行 Vitest 或运行器测试作为任务关卡。
5. 独立评审 Agent 使用全新临时会话，检查原反馈、候选差异、同版本检查结果和验证记录。要求修改时意见返回原做事 Agent；只有代码版本不变时才复用已通过的评审。
6. 部署检查和评审通过的同一构建，交两个不同账号真人验收。这里不启动第二个浏览器复测 Agent。真人未通过时意见回到原做事 Agent，继续已有代码和调查结果。两人通过后更新本地集成版本，并将本次验收的产品文件合并到主开发目录，保留其他本地改动和 Git 暂存区。无法干净合并时保留文件，控制台明确显示开发目录未同步，并提供已更新运行版的链接。没有远程 PR 或生产发布。

## 连续会话与恢复

做事 Agent 使用非临时 Codex CLI 会话，保存实际 `thread.started` 的 ID；后续通过 `exec resume <id>` 继续。检查错误、范围补充、评审及验收意见均回到同一个任务、同一个工作目录的会话；重启服务或中断后会话 ID 仍保留。工作目录因基线迁移发生变化时开新会话，并提供保存的根因和具体失败记录，不把旧目录会话接到不同候选上。

源码工具返回文件哈希和有界片段，支持批量读取及局部补丁。浏览器使用独立合成用户和数据，只访问指定本地预览。预览在代码检查前关闭，避免开发编译与正式构建互相覆盖。预览端口默认为测试版端口加 10（本机 3052，内部 3053）。附件只允许读取本条反馈上传的图片。

做事 Agent 的验证结论需要修改后的真实操作记录。缺少证据记录为未验证，不冒充通过。验证工具不足不自动要求重新开发，真人验收界面列出未覆盖项。具体产品错误、危险修改、真正的无进展仍会阻止继续。

## 启动与入口

主项目依赖 `npm ci`；运行器依赖 `npm ci --prefix rsi --ignore-scripts`。复用本机已有 Codex CLI 登录，Windows 使用 Edge。

- `RSI_HOME` 必须位于源码目录外，保存配置、数据库、候选代码与记录。
- `npm run rsi:background` 启动；`npm run rsi:status` 查看；`rsi:pause` / `rsi:resume` / `rsi:stop` 控制服务。
- 默认本地入口 `http://127.0.0.1:3040/_rsi/login`，控制服务 3044，测试版 3042。
- 本工作区最新开发页面为 `http://127.0.0.1:3050/_rsi/login`，直接使用主目录页面源码。
- 重启保留暂停状态；管理员可点击“巡检一次”或“处理一条反馈”。

## 预算与历史兼容

运行目录 `config.json` 的主要设置：`agentModel` 默认 `gpt-6.1-sol`；每修复周期 `maxTaskTokens=3000000`、`maxTaskCalls=16`、`maxRepairRounds=5`；临时调用阶段最多尝试 2 次，故障累计最多 6 次。开发和评审默认 high，巡检 medium。

Token 在每次调用结束后结算，单次可能超过余额；达到上限不再开始下一次调用。未返回用量的失败仍计调用次数。历史累计仅统计，不设总上限。预算耗尽和主动中断保留现场，等待手动恢复；不会自动空跑。控制台展示每个任务的 Token、模型、连续会话 ID 和按需求验证结果。

旧任务、旧检查、诊断和 QA 历史继续保留；旧的待验收版本不会因流程更新重新开发或被自动批准。旧候选缺少新验证记录时明确交真人确认。

全部本地体验使用合成账号和隔离数据库，Mobius/Time off 外部同步关闭。正式服务器需要配置其自身的模型登录、运行数据和受限运行账号。

## 副本自动清理

验收通过并完成本地更新后、验收不通过后、任务暂停/转人工后，以及服务启动时加入清理队列。后台空闲时分批执行，并每六小时补查。管理员可在自动优化页点击“立即清理副本”；无需调用模型。

保留当前运行版、一个上一运行版、所有未完成任务唯一的候选目录及待验收构建。真人验收不通过仅移除旧测试版，候选及连续会话保留。已结束任务的代码先保留 Git 归档引用、完整差异和未提交文件，再移除工作目录；重新交给 Agent 时可从归档重建候选。已经成功集成的任务再次提出新要求时，从当前基线开始，不重复应用旧补丁。

自动清理仅处理当前仓库登记、且位于已授权运行目录内的工作目录。其他开发/发布工作目录保留。依赖 junction/symlink 仅删除链接，不遍历目标。遇到被忽略的个人配置、数据库或上传目录时保留整个副本并记录原因，不删除用户数据。Git 提交、任务数据库、补丁、模型用量、评审、日志和截图不清理。

清理前重新核对任务、进程和版本引用，归档后再次核对文件状态。中断的删除保留原始归档并标记待检查，不将部分删除后的状态当作新的原始代码。清理结果和保留原因显示在控制台；完整报告位于运行目录的 cleanup/reports，源码恢复资料位于 cleanup/archives。清理失败不会将已成功的版本更新标成失败。
