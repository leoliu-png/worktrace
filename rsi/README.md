# WorkTrace 持续自动优化（本地版）

这是一套独立于聊天会话运行的常驻服务。启动后，定时体验、读取反馈、开发、检查、独立评审和部署本地测试版均由服务调度。无需每一轮再给聊天 Agent 下指令。

## 启动

1. 在项目目录安装现有依赖：`npm ci`。
2. 安装运行器依赖：`npm ci --prefix rsi --ignore-scripts`。
3. 确认本机已有 Codex CLI 登录；本系统复用现有登录，不保存、复制或输出登录凭据。
4. Windows 默认用已安装的 Edge 创建独立无头浏览器，不使用个人浏览器资料。其他平台运行 `npm run browser:install --prefix rsi`，并将运行配置的 `browserChannel` 设为空字符串。
5. 执行 `npm run rsi:background` 在后台常驻运行；也可以用 `npm run rsi:start` 前台查看日志。后台运行不依赖本聊天或终端继续打开。
6. 打开 `http://127.0.0.1:3044`，进入 WorkTrace 的“自动优化”控制台。首次构建需要几分钟。

本地验收账号入口：`http://127.0.0.1:3040/_rsi/login`。选择管理员 A/B 或普通成员即可进入，无需 Google 授权。首页和误入的 Google 登录错误页会回到这个入口；正式环境的 Google 登录配置不受影响。控制台与测试版分别保存账号选择，打开测试版不会切换控制台账号。

默认运行目录位于项目同级的 `service-runtime`，也可在启动前用 `RSI_HOME` 指定绝对目录。运行目录必须在源码目录之外。源码和运行数据分离，不提交数据库、凭据、日志和浏览器截图。

## 持续链路

1. 每小时，用户 Agent 在独立浏览器会话体验一组轮换场景。有可靠发现时，复现并通过 WorkTrace 现有“建议反馈”表单提交；没有发现也如实记录。
2. 每分钟读取本地反馈，同一反馈 ID 只入队一次；相似内容指纹只关联历史，不阻止未完成建议继续执行。整理 Agent 将模糊、高风险、越界任务转人工，只自动批准明确且范围较小的界面/编辑体验改进。
3. 做事 Agent 在新 Git 工作目录运行，使用独立会话和受限源码 MCP：可以读取允许的产品源码，只能写入已批准的文件，写入前核对内容哈希。Agent 不使用主机命令行，不读取生产配置，不直接提交或合并代码。
4. 调度器验证修改范围、文件数量和凭据痕迹，再创建本地提交；执行基础 lint、类型检查、全量测试和构建。测试不能少于基线。
5. 独立 Review Agent 只收到原始反馈、固定版本差异、相关源码和检查证据，不收到开发者对话。结果为 Approve / Request changes / Escalate。
6. Approve 且四项检查通过、版本和产物未改变，才复制同一构建产物到独立发布目录并启动本地测试版。独立浏览器 Agent 复测原始问题和失败路径；失败继续打回。
7. 每个修复周期默认最多五轮有效代码修复。未产生代码改动的连接失败不占修复轮次；同一轮内的续接使用同一个轮次标识，只计一次。每个阶段最多三次调用，分别等待 15 秒、45 秒重试；仍失败则退避五分钟，从保存的阶段继续。每个周期默认累计最多六次临时调用故障，耗尽后标记人工处理。每天的调用总额仍计入失败调用。默认每天最多六项开发任务、十六次 Agent 调用，当前本机测试配置提高到一百次；日期额度以北京时间计算。
8. 测试版通过后，在控制台显示待验收通知。两名不同登录账号批准同一个提交后，更新 `codex/rsi-local-integration` 本地集成分支与本地应用；原始 main 分支不变。

## 控制与恢复

- 范围规划会读取当前页面、表单及其导入关系。筛选不能仅凭路由猜测修改范围，也不能把“正在填写反馈”扩展成“新增已提交反馈编辑功能”。必要组件不在范围内时，独立范围 Agent 根据原始反馈、真实源码与现有改动重新批准最小范围，并记录批准文件和需求对应说明。
- 开发 Agent 发现缺少必要产品文件时返回结构化范围申请，不能自行越权写入。调度器先复核申请、检查硬性文件边界及已保存候选的覆盖范围，再在原任务、原修复轮次中继续。每个周期最多完成三次范围复核，网络调用失败仍按调用故障预算处理。认证、数据库、依赖、外部集成及 RSI 运行器仍不属于自动扩大的范围。
- 控制台显示“复核修改范围”和可展开的范围调整记录。没有写入源码的范围申请只计 Agent 调用，不占有效代码修复轮次；已有源码、检查结果及历史记录均保留。范围改变后重新进行代码检查、独立评审和浏览器复测，最终仍需两名真人验收。

- 每条任务保存结构化历史问题，包括独立评审的文件/行号/修复要求、浏览器复测失败步骤和证据、失败检查的日志。新修复周期继承这些记录，并从旧运行记录补回此前遗漏的评审/复测问题。开发、整理和复测读取问题记录；独立评审只读取独立问题证据、原需求和当前版本，不接收开发对话。控制台可展开“历史问题记录”，旧失败是否已经解决仍以当前版本验证为准。
- 浏览器复测先按批准范围生成检查计划，故障夹具按计划开放。日志链接任务不触发反馈表单的 503 测试；无关观察单独记录，不扩大当前任务范围。工具回执与 `navigation.jsonl` 保存实际 `window.open` 调用及被拦截的导航请求，验证请求目标时无需访问外部服务；这不代表外部网站可用。
- 浏览器 `paste` 派发合成文本事件，`paste_image` 在批准的图片验收任务中生成固定 PNG 并派发图片事件；不读取主机文件或系统剪贴板。每个快照返回粘贴回执、编辑器图片与文件关联，以及日志/反馈提交回执。日志保存失败替身只中止本地保存请求，不执行服务端写入；不能声称模拟了数据库故障。
- 用户巡检浏览器可以使用本地普通成员登录入口或切换两个合成成员账号；管理员入口和外部地址仍受限制。若巡检场景因访问或工具问题受阻，会记录为未完成，并在下轮继续同一场景。
- 浏览器复测默认最多五次，与每阶段最多三次临时调用重试分开计数。按当前验收计划（含独立评审请求）事先开放必要能力；新工具版本、候选或验收要求产生新的验证记录，历史保留。已通过的同版本验证证据继续沿用，优先复测缺失项目；不消耗额外代码修复轮次，也不直接要求开发修改业务代码。开发已产生范围内改动时，即使说明中写有“等待协调器验证”，仍先验证改动，保留说明供独立评审判断；不会仅凭这句话提前转人工。真正无法实施且无改动的阻塞仍需人工处理。

- 反馈的“处理状态”和“处理方式”分别保存。未标记已完成且选择“Agent 处理”的反馈均可进入队列，包括重复建议；只有已完成或明确标记“人工处理”的反馈会被跳过。当前结构化处理方式优先于历史回复、旧转人工说明和重复标签，筛选 Agent 不能据这些旧文字取消本次处理。管理员在“反馈管理 → 处理这条反馈”切换方式，普通成员只能看到标记。运行中改为人工处理时，当前步骤结束后不再进行下一步调用、部署或集成。
- 真人点击“验收不通过，交回 Agent 修复”并填写至少八字的意见后，原反馈保持处理中，附带验收人、版本及具体意见重新排队。创建新的有限修复周期，保留原候选代码、所有调用记录、评审和验收历史；重新整理允许范围，再走开发、检查、独立评审和浏览器复测。新候选仍需两名真人验收。自动运行暂停时保持暂停，可手动触发该反馈。
- 已转人工的历史反馈不会自行重启。要继续处理，在反馈管理切换为“Agent 处理”，选择未完成状态即可，补充要求可不填；仍由 Agent 处理的反馈可勾选“根据补充要求，让 Agent 再处理一轮”。只有新的真人反馈或管理员明确交回才创建周期，重复提交同一验收版本不会重复增加额度。重启、普通回复、状态轮询和自动重新排队均不会创建周期；每日总额度仍有效。

- 控制台分别显示后台连接、自动运行开关、当前 Agent/任务阶段、执行时长、最近一步操作和排队情况。暂停时不再显示已过期的自动巡检时间。
- 调用超时会强制结束等待；即使子进程已退出但后代仍占用输出管道，也不会无限等待。服务重启会回收已中断的运行记录并保留证据及调用次数；未完成的巡检明确显示失败，不冒充有效巡检。控制台会区分后台在线与调用超时。
- “巡检一次”可以在自动运行暂停时执行一轮体验，完成后仍保持暂停；不会自动开发已转人工的反馈。请求持久保存，重复点击不会重复排队。
- “处理一条反馈”立即读取最新反馈，选择最早一条等待处理的反馈，执行筛选、开发、检查和构建、独立评审、本地测试版部署和浏览器复测；队列任务也可点击“手动处理此反馈”指定目标。通过后仍需两名真人验收。手动请求持久保存并去重，暂停时也能执行，且不改变自动运行开关。不会绕过每日调用/任务额度、累计开发上限、故障退避或待验收任务；没有新反馈时显示明确提示。临时失败仅恢复同一目标，不会自动接着处理其他反馈。
- 已标记人工处理的反馈不再提供旧的重试入口，改由反馈管理中的明确交回操作恢复。“结束自动处理并转人工”的说明选填，会保存人工标签，不调用 Agent；按钮旁显示处理中、成功或失败消息，这不代表功能已修复。历史重试记录和累计次数保留。
- `npm run rsi:status` 查看完整状态；`npm run rsi:pause`、`npm run rsi:resume` 控制运行；`npm run rsi:stop` 正常停止服务及监督进程。
- SQLite 保存队列、运行阶段、反馈关联、审查结果、验收版本和事件；通过租约避免同时启动两套服务。
- 监督进程在服务异常退出后退避重启。执行中断的任务保留旧证据，最多三次恢复到新目录重新排队；上次 Agent 尚在运行时先等待，避免并行重做。待验收版本启动时会校验并恢复。
- 正常停止会保留队列、允许范围、候选代码以及当前检查/评审/复测阶段；暂时调用失败先在当前阶段限次重连，再退避五分钟续接。有效代码修复和临时调用故障分别计数，达到各自上限后才转人工；认证、安全、越界或人工裁决问题会直接转人工。额度耗尽后等下一日继续。
- 恢复时只复用同一提交和未变化构建产物的检查/评审结果。本地集成基线变化时，保留原候选改动并迁移到新的隔离目录，重新检查和评审；原目录和证据保留，冲突或越界则转人工。
- 启动时依据实际错误日志及源码写入记录纠正旧版连接故障误占修复额度的问题。仅恢复确实因此过早停止的任务；已由人工结束的任务保持结束，未知失败按原记录保守计数。不会清空调用历史或自动开启已暂停的服务。
- 开发和独立评审默认使用 high 推理强度（可配置为 medium）；开发在同一轮核对全部验收项、既有评审意见和编辑器生命周期，评审集中报告有具体代码路径或复现依据的实质问题。各角色仍使用独立会话，检查和真人验收要求保留。
- 本机休眠、关机期间不会运行；开机后重新启动可恢复持久状态。本版未注册系统开机启动项。

## 本地范围与边界

- 全部应用使用单独的合成账号、日志、数据库和上传目录。不会载入源码原始 `.env`，Mobius、Time off 和其他外部同步关闭。
- 用户 Agent 的浏览器工具只允许指定的本地地址；不能执行脚本、读取源码、进入管理页或进行删除/权限变更。
- 浏览器复测使用与巡检库分离的测试库，可提交一条带 `[RSI验收]` 前缀的合成反馈验证成功路径；测试反馈不会进入巡检反馈队列。复测工具还提供固定的存储不可用、草稿损坏、反馈提交 503 场景，不接受调用者传入脚本。
- Agent 会话使用只读沙箱，做事 Agent 的写入单独通过限定路径的源码工具；独立评审不提供写入工具。运行器配置、认证、数据库、外部集成、依赖、CI 和 RSI 自身代码均不属于自动修改范围。
- 当前宿主上的构建和本地 Web 应用仍以启动者身份运行。基础 lint 和差异检查不等于完整安全审计；接入真实数据或无人值守服务器前，应把构建/Web 应用放入容器或受限系统账号，补齐隔离与运维。
- 本地演示提供验收账号 A/B，供验证界面和不同账号约束；它们不证明两名真实员工的身份。正式验收应使用项目现有的真实登录账号。
- 本地 PR 草稿和补丁保存在运行目录。按当前“只在本地尝试”的要求，没有 GitHub 推送、远程 PR、远程通知或生产发布命令。生产发布保留独立人工确认，后续再接部署适配器。
